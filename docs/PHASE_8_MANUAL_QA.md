# Phase 8 — ручная приёмка результатов и экспорта

Дата: 2026-08-31
Статус: обязательная ручная проверка владельцем перед Phase 9

## Подготовка

1. Запустите проект командой `npm run dev`.
2. Откройте Organizer workspace: `http://127.0.0.1:5173/app/results` (используйте порт, показанный терминалом).
3. Выберите опубликованный тест, для которого уже есть хотя бы одна попытка. Если попыток нет, пройдите тест по его коду в отдельном браузере или приватном окне и отправьте ответы.

## Проверка

1. **Обзор.** Убедитесь, что название и статус выбранного теста верны. Значения «Начали», «Завершили», «Средний балл» и «Участие» не должны быть демонстрационными: после новой попытки они меняются после обновления страницы.
2. **Пустое состояние.** Выберите опубликованный тест без отправленных попыток. Должны отображаться нули, прочерки и сообщение «Завершённых попыток пока нет», без фиктивных графиков.
3. **Распределение и динамика.** Вернитесь к тесту с отправленными результатами. Количество в четырёх диапазонах в сумме должно совпадать с числом оценённых завершённых попыток; график показывает реальные даты завершения.
4. **По вопросам.** Откройте вкладку «По вопросам». Для оцениваемого вопроса проверьте количество ответов и процент правильных; для шкалы — среднюю оценку или прочерк, если ответов нет.
5. **Попытки.** Откройте вкладку «Попытки», найдите участника через поиск и нажмите строку. В модальном окне должны быть статус, итог, ответы и правильный ответ для ошибочно отвеченного оцениваемого вопроса.
6. **Незавершённая попытка.** Откройте активную или прерванную попытку. Итоговый балл должен быть прочерком; интерфейс не должен показывать начисленные за вопрос баллы как финальный результат.
7. **CSV.** Нажмите «Экспортировать». Должен скачаться `vecta-results.csv` с заголовками и попытками только выбранного теста. Русский текст должен открываться без повреждённой кодировки.
8. **Переключение теста.** Выберите другой тест в списке. Все три вкладки должны обновиться, не смешивая попытки и показатели двух публикаций.
9. **Адаптивность.** При ширине около 390 px проверьте обзор и попытки: горизонтального выхода контента за экран нет, вкладки прокручиваются, модальное окно деталей помещается по ширине.
10. **Консоль.** Во время шагов 1–9 в консоли браузера не должно быть красных ошибок.

## Что сообщить

- Если всё прошло: `Phase 8 принята`.
- Если есть ошибка: номер шага, название выбранного теста, фактическое поведение и скриншот.
