# Vecta — ручная приёмка Phase 7

Статус: обязательная проверка владельцем перед Phase 8
Среда: локальный runtime `http://127.0.0.1:4173`

## Перед началом

1. Запустить `npm run dev` и открыть `http://127.0.0.1:4173`.
2. Для каждого независимого сценария создавать новый тест. Старые коды, созданные до перехода на HMAC digest, использовать не нужно.
3. Для проверки «нового участника» использовать приватное окно/другой профиль браузера. Open mode хранит best-effort identity в local storage, а attempt token — только в session storage.
4. Локальный Turnstile использует официальные тестовые ключи Cloudflare и проходит автоматически. Реальный production widget появится только в Phase 11.

## Сценарий A — открытый тест, autosave и результат

1. Войти как Organizer, открыть «Тесты» и создать новый черновик.
2. Добавить минимум один обязательный вопрос с одним вариантом ответа и отметить правильный вариант.
3. В настройках выбрать открытый доступ, одну попытку и включить показ результата участнику.
4. Опубликовать тест и скопировать код либо публичную ссылку.
5. Открыть ссылку в приватном окне, указать имя и продолжить.
6. Подтвердить инструкцию, начать тест, выбрать ответ и дождаться подписи «Ответ сохранён».
7. Обновить страницу. Ожидается: та же попытка восстановлена, выбранный ответ сохранён.
8. Перейти к проверке ответов и отправить их. Ожидается: экран завершения показывает балл и максимум, но не показывает правильный ответ.
9. Ещё раз обновить страницу. Ожидается: завершённая попытка не создаётся заново и повторная отправка недоступна.
10. Снова открыть тот же код в том же профиле. Ожидается: повторная попытка заблокирована.

## Сценарий B — выход расходует попытку

1. Создать и опубликовать новый открытый тест с одной попыткой.
2. Открыть его как новый участник и начать отвечать.
3. Нажать «Выйти из теста». Ожидается: предупреждение явно сообщает, что попытка будет использована.
4. Сначала нажать «Продолжить тест». Ожидается: модальное окно закрыто, попытка активна.
5. Снова нажать «Выйти из теста» и подтвердить. Ожидается: возврат на главную, попытка имеет состояние `abandoned`.
6. Повторно открыть тот же код в том же профиле. Ожидается: доступ к новой попытке не выдаётся.

## Сценарий C — результат скрыт

1. Создать новый тест, выключить «Показывать результат участнику» и опубликовать.
2. Пройти тест в новом приватном контексте и отправить ответы.
3. Ожидается: видно подтверждение завершения, но нет балла, максимума и answer key.

## Сценарий D — контролируемые приглашения

1. Создать новый тест с контролируемым доступом и опубликовать.
2. В разделе распространения добавить по одному имени/идентификатору на строку и создать приглашения.
3. Скопировать одну персональную ссылку до обновления страницы.
4. Обновить Organizer-страницу. Ожидается: список приглашений остаётся, но исходные секретные ссылки больше не показываются.
5. Открыть скопированную ссылку в новом приватном окне, пройти и отправить тест.
6. Повторно открыть ту же ссылку. Ожидается: приглашение использовано, новая попытка не создаётся.
7. Создать ещё одно приглашение, отозвать его до использования и открыть ссылку. Ожидается: доступ запрещён.

## Сценарий E — негативные состояния

1. Ввести несуществующий код. Ожидается: понятное сообщение, технические детали и конфигурация не раскрываются.
2. Закрыть опубликованный тест в Organizer UI и открыть его код как новый участник. Ожидается: состояние «тест закрыт».
3. Несколько раз быстро нажать отправку после подтверждения. Ожидается: создаётся один итог, без дублей и повторного начисления.

## Критерий приёмки

Phase 7 закрывается только если все сценарии проходят без потери ответа, раскрытия answer key, повторного использования попытки/приглашения и непонятных тупиковых экранов. Любое отличие нужно сообщить с названием сценария, номером шага и скриншотом.
