# Vecta — Low-Fidelity Wireflows

Статус: Phase 3, основа для GPT Image 2 и Product Design
Дата: 2026-08-29

Этот документ фиксирует структуру и поведение. Он не задаёт финальную палитру, декоративный стиль или компоненты.

## 1. Organizer: создание и публикация

`Обзор → Создать тест → Новый draft → Редактор → Preview → Checklist → Публикация → Распространение`

### Обзор

- Постоянная навигация и контекст организации.
- Заголовок «Тесты» и одно главное действие «Создать тест».
- Один приоритетный блок активной публикации: статус, ответили/приглашены, средний балл, переход к результатам.
- Компактный список последних тестов: название, статус, обновление, участие, контекстные действия.
- Empty state объясняет первый шаг и повторяет одно главное действие.
- Основное представление списка тестов после выбора владельца — drag-and-drop board с колонками «Черновики», «Запущены», «Завершены».
- Перетаскивание draft в «Запущены» открывает publication checklist; перенос запущенного теста в «Завершены» требует подтверждения закрытия. Обратный перенос запрещён правилами lifecycle. Для клавиатуры и touch доступно эквивалентное действие «Переместить».

### Новый draft и редактор

- Первый экран запрашивает только название; создание draft не требует заполнить все настройки.
- Desktop: слева упорядоченный список вопросов, в центре текущий вопрос, справа компактные свойства вопроса/теста.
- Mobile: список вопросов и редактор открываются последовательно; свойства — в bottom sheet.
- Типы: один вариант, несколько вариантов, шкала.
- Для оцениваемых вариантов задаются правильные ответы и целое число баллов; шкала не оценивается.
- Autosave показывает только состояния «Сохранение…», «Сохранено», «Не удалось сохранить»; ошибка не уничтожает локальный ввод.
- Удаление вопроса требует подтверждения и показывает, что действие обратимо до следующего сохранения только если это реально реализовано.

### Preview и публикация

- Preview визуально отделён от настоящей попытки и не создаёт attempt/result.
- Checklist блокирует публикацию при отсутствии вопросов, вариантов, answer key или обязательных настроек.
- Перед публикацией явно указано: будет создана неизменяемая версия; дальнейшие изменения потребуют новой версии.
- После успеха — переход к распространению без промежуточного celebratory-экрана.

## 2. Participant: открытый режим

`Главная/прямая ссылка → Код + имя → Проверка → Инструкция → Вопросы → Проверка ответов → Отправка → Завершение`

- На `/join` код и отображаемое имя находятся в одной короткой форме.
- Ошибка кода объясняет, что исправить; closed/expired показываются в закрываемом модальном окне поверх затемнённого onboarding, а не на отдельной пустой странице.
- Инструкция показывает название, количество вопросов, ориентир по времени, правило возврата к вопросам и результат после отправки.
- Вопрос: номер и общий прогресс, формулировка, ответ, «Назад» и «Далее». Прогресс не притворяется таймером.
- Ответ сохраняется сервером; при кратком сбое пользователь может повторить сохранение без потери выбора.
- Review группирует «Отвечено» и «Без ответа»; отправка требует явного подтверждения.
- При `showParticipantResult=false` завершение показывает только успешную отправку.
- При `showParticipantResult=true` дополнительно показываются «Набрано» и «Максимум», но не правильные ответы и не answer key.

## 2.1. Public onboarding и вход

- Первый viewport одновременно объясняет Vecta и показывает рабочий entry UI; пользователь не ищет отдельную кнопку входа.
- Organizer action передаёт управление выбранному managed auth без имитации собственной парольной формы.
- Participant вводит общий код прямо на главной; отображаемое имя запрашивается следующим шагом только после успешной проверки кода.
- Под hero показываются только проверяемые факты продукта: три типа вопросов, два режима участия и единое рабочее пространство. Customer counts, testimonials и другие недоказанные marketing claims запрещены.
- Следующий блок объясняет три шага: создать тест, поделиться доступом, следить за результатами. Реальный preview интерфейса используется вместо декоративной AI-иллюстрации.

## 3. Participant: контролируемый режим

`Персональная ссылка → Обмен токена → Инструкция → Вопросы → Проверка → Отправка → Токен использован`

- Fragment-токен не отображается в UI и очищается после успешного обмена.
- Имя участника берётся из приглашения или запрашивается только если это разрешено публикацией.
- Повторный обмен использованного токена показывает нейтральный терминальный экран без деталей чужой попытки.
- Одно приглашение допускает одну завершённую попытку; спорные повторы решаются сервером.

## 4. Organizer: результаты

`Обзор тестов → Активная публикация → Результаты → Вопросы / Попытки → Детали / Экспорт`

- Summary: ответили/приглашены, завершили, средний балл, распределение результатов и динамика участия.
- Не смешивать шкальные ответы с балльной успеваемостью; шкала имеет собственное распределение.
- Анализ вопросов показывает долю правильных ответов только для оцениваемых типов и распределение выбора без раскрытия лишних персональных данных.
- Список попыток содержит имя/идентификатор, статус, время, балл (если применим) и режим участия.
- Экспорт запускается из результатов, сообщает состав данных и имеет состояния preparing/ready/error.
- Empty state «Ответов пока нет» ведёт к распространению, а не показывает нулевые графики.

## 5. Регистрация Organizer

`Email → Turnstile → шестизначный OTP → личное пространство → Обзор`

- Один и тот же интерфейс используется для первого входа и возврата существующего организатора.
- После первого подтверждения сервер создаёт личное пространство; роль и organization ID не выбираются клиентом.
- Ошибки доставки и проверки показываются в доступной modal поверх onboarding, без отдельной пустой страницы.

## 6. Общие состояния

### Глобальные overlays

- Меню профиля привязано к profile trigger, закрывается по Escape/outside click и возвращает focus на trigger.
- Help drawer открывается справа, сохраняет контекст текущего экрана, имеет доступный заголовок/close action и не блокирует восстановление focus после закрытия.
- Role-choice вход разделяет Organizer managed auth и Participant code/token flow, не создавая постоянный participant account.

### Loading

- Скелетон повторяет реальную структуру, не блокирует весь shell.
- Для participant submit используется явный blocking state, предотвращающий повторную отправку.

### Empty

- Сообщает причину пустоты и одно следующее действие.
- Не использовать декоративные иллюстрации и emoji как замену инструкции.

### Error

- Inline error рядом с исправляемым полем.
- Page-level error для загрузки данных содержит «Повторить» и безопасный путь назад.
- 404, invalid/expired code, closed test и rate limit имеют разные тексты и действия.

### Accessibility

- Полная клавиатурная навигация, видимый focus, семантические labels и live regions для save/submit.
- Цвет не является единственным признаком статуса или правильности.
- Touch targets не меньше 44×44 CSS px; текст и ключевые элементы соответствуют WCAG AA.
- Reduced motion отключает необязательные переходы.

## 7. Responsive rules

- Desktop design target: 1440×1024; рабочая ширина контента ограничена, но таблицы используют доступное пространство.
- Tablet: навигация сворачивается, трёхпанельный редактор становится двухпанельным.
- Mobile: один главный столбец; фиксированная нижняя панель действий только в редакторе и попытке.
- Порядок контента и названия действий одинаковы на desktop/mobile.
- Графики получают табличное/текстовое представление для узких экранов и assistive technology.

## 8. Ограничения визуального направления

- Бренд Vecta; старые Gazprom/Oprosnik logo и стили не переносятся.
- Эмоциональная основа берётся из legacy-продукта: дружелюбность, свет, простой вход в сценарий и спокойный узнаваемый синий. Итоговый интерфейс не должен ощущаться строгой административной системой или агрессивным enterprise-dashboard.
- Без неона, glassmorphism, emoji, декоративной 3D/AI-геометрии, случайных градиентов и «card soup».
- Один доминирующий action на экран; вторичные действия визуально спокойнее.
- Типографика, интервалы и данные создают иерархию сильнее, чем тени и контейнеры.
- Тексты и данные выглядят правдоподобно; никаких несуществующих MVP-функций.
